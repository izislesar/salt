Pillar SLS files that compile pillar again while they are being rendered -- for
example ``{% set data = salt['pillar.items']() %}`` -- no longer recurse until
Python's recursion limit is reached, which flooded the master log with
tracebacks and made the minion time out waiting for its pillar. Salt now detects
the re-entry and reports a single pillar render error that names the supported
alternatives. The Jinja error formatter also no longer masks the real error with
``TypeError: 'NoneType' object is not subscriptable`` when a traceback contains
no template frame.
